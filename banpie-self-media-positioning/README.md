# 半撇自媒体定位助手

由半撇创作，帮助个人和企业找到适合自己的自媒体账号方向，也能根据已有内容、用户反馈和业务结果调整定位。

定位就是明确主要分享什么、给谁看、提供什么价值，以及为什么别人愿意持续关注。助手先介绍自己、用通俗语言解释定位，再说明步骤；已有资料也不会直接跳到方案。

## 同一套模板，按已有信息推进

资料固定分为三组：简历（基本情况与经历）、个人说明书（个人特点与价值观）、运营条件（做账号的目标与可投入条件）。不要求准备三个文件，直接讲述或提供现有材料都可以。

- 没有资料：展示完整模板和一个填写案例，等待补充。
- 部分资料：按同一模板代填已有信息，只补影响判断的缺口。
- 资料足够：完整列出已知信息、来源和未知项，等待核对并同意生成。

模板补充最多一轮、两个问题；不会填可说“带我聊”，默认三问后整理、首次最多五问。可以留空或说“不问了”，达到上限也带着未知项进入资料确认，不无限追问。生成后比较方向，用户选定再展开定位卡与账号呈现。

## 不同使用方式共用规则

[统一提示词](https://github.com/banpie/banpie-skill-self-media-positioning/blob/main/prompts/自媒体定位统一提示词.md) 可用于 Agent 配置或普通对话，由技能正文自动导出，不独立维护另一套方法。导入配置不会自动更新其他平台旧副本。维护者可以在技能目录运行：

```bash
python3 scripts/export_prompt.py --output /path/to/统一提示词.md
python3 scripts/export_prompt.py --output /path/to/统一提示词.md --check
```

使用定位助手本身无需运行脚本。

## 按你的情况开始

首次启动时，先用一句定义和案例解释“定位是什么、如何完成、会得到什么”，随后边做边理解；不需要预先掌握专业术语或通过测验。有经验只缩短解释；明确要求省略介绍时可跳过介绍。无账号不等于零经验，企业也可能从零起步。

| 当前场景 | 重点 |
| --- | --- |
| 完全没有账号 | 从具体经历与可投入条件找到能尝试的方向，不要求历史数据 |
| 少量试发 | 利用已有作品给有限判断，不凭一条内容定成败 |
| 企业、创始人或团队 | 对齐业务目标、客户问题、内容资源与账号角色 |
| 已有账号遇到瓶颈 | 先找值得保留的部分，再区分定位、内容与承接问题 |
| 成熟账号或大 V 转型 | 评估已有受众与资产，比较相邻栏目、渐进调整或独立探索的代价 |

这些场景可以交叉，按本次问题选择流程，不用先填写分类问卷。详见 [场景适配](references/scenarios.md)。

## 安装

在支持 Agent Skills 的客户端中，把下面这段话发给智能体：

```text
请从这个项目安装 banpie-self-media-positioning，只安装这一个技能：
https://github.com/banpie/banpie-skill-self-media-positioning/tree/main/banpie-self-media-positioning
安装后检查技能入口及其引用文件能否读取，告诉我结果，先不要开始定位。
```

也可以将发布包内的 `banpie-self-media-positioning` 完整目录放入客户端支持的技能目录。具体导入位置、自动发现和重载方式以该客户端为准；安装后新开对话。通用格式不代表已逐一实测所有客户端。

核心不需要额外密钥、账号登录或其他技能。联网研究和保存文件取决于客户端能力；没有网络时会明确标注未核验部分，没有文件能力时会提供可复制的定位文档与续聊摘要。

## 开始使用

```text
使用 banpie-self-media-positioning 帮我找自媒体定位。先介绍定位、步骤和本轮终点，再给我简短模板和一个参考案例；历史记忆不能代替这次资料。收到后按模板列出全部已知信息，请我核对是否对应这次账号、是否开始生成；我确认前不要输出定位。
```

企业可直接说：

```text
使用 banpie-self-media-positioning 帮我们企业确定账号方向。先给适合企业的填写模板和案例；我们不一定要做老板个人号，请结合业务目标和团队资源判断。
```

已有资料时，可以直接发个人介绍、产品说明、作品、用户提问或账号数据，并指定允许读取的文件。没有资料也可以只讲自己的情况，不要求先写出目标受众、商业模式或完整定位。

[查看个人与企业填写模板及完整案例](references/intake.md)，或 [从填写到定位的完整示范](references/worked-example.md)。案例均为虚构，只示范具体程度，不是需要照着包装的履历。

## 首次流程与加载排查

流程为：介绍定位 → 收集与整理资料 → 核对资料并确认生成 → 比较候选 → 选定后形成定位卡与测试。资料不足时，先给已填部分的模板与案例，等待你补充；资料齐全时，助手代填完整模板，请你核对并确认是否生成。首条消息已经带足资料也不能直接出定位，历史资料要标明来源与待核对项。

首次显示 `自媒体定位助手 · 0.4.2`，每次回复显示当前阶段。这是检查流程的线索，模型自报版本本身不能证明技能已加载。技能是对话指令，不是宿主程序强制执行的状态机；未加载时，正文里的规则无法约束宿主。

在在线 ChatGPT 中，优先从已安装技能详情点击“在聊天中试用”，或新对话输入 `@` 选择该技能。仅用文字说技能名称，可能变成目录搜索。显式调用方式见 [OpenAI 官方说明](https://learn.chatgpt.com/docs/plugins)。遇到问题可发送：

```text
请实际加载已安装的自媒体定位助手。读取失败就说明，不要用通用定位建议代替；读取成功后按正文从第1步介绍流程，按模板整理资料并等待我核对、确认是否生成。
```

安装、加载、按流程运行是三个不同的检查。若回复说“插件没有启动”却继续给定位，应先排查加载，不能将该回复当成本技能的结果。已读正文但附件缺失时，应报告具体文件，不能假称读取成功。

本地 Git 更新与在线 ChatGPT 的技能更新是两条独立路径：本地 `git pull --ff-only` 不会改动已上传的在线副本，在线版需要在技能页面更新并新开对话。[OpenAI 对不同技能生命周期的说明](https://learn.chatgpt.com/docs/enterprise/skills)。

## 资料齐全时会怎样开始

助手按个人、企业或兼容模板列出简历、个人说明书、运营条件的全部维度及已知细节，来源与未知项就近标明，然后询问：“以上资料是否对应你这次要做的账号？如果准确，是否现在据此生成定位？”

你可以修改资料，或直接回复“可以，开始”。不要求特殊口令，也不会拆成两轮审批。只纠正资料时先更新表；纠正的同时说“按修改后的生成”就直接继续。补问达到上限时，带着未知项进入同一个确认环节，不无限追问。

## 你会得到什么

- 确认生成后给简短判断：首选、事实依据、代价或未知、第一步；需要时比较最多三套候选，并说明什么证据会改变推荐。
- 选定后的定位卡：服务谁、提供什么内容、为什么可信、如何持续做，以及五项账号定位、真实身份、可信能力、价值观和表达特点。
- 内容支柱、示例选题和符合时间精力的有限测试。
- 老账号的证据诊断：区分定位、内容表达、分发和业务承接，不凭一条低播放建议换方向。

个人表达、职业机会、品牌信任、招聘、客户教育、获客或收入都可以作为目标，不强制变现。

## 深入、保存与复盘

可以继续说“深入研究这两个方向”“我选第二个，展开定位卡”“把目前结果保存下来”或“根据这些反馈更新定位”。

进入深度研究后，有联网能力就检查真实需求、同类内容和替代方案，并记录来源与证据缺口。用户选定只代表采用一个待验证假设，不代表市场验证成功，也不承诺涨粉或收入。

有文件能力时默认保存为 `自媒体定位.md`，优先更新已有同一账号文档；多账号分开保存。新会话提供该文档即可继续，避免重新填写。

本技能不自动发布内容、修改公开账号、联系客户或购买数据。账号名称、头像方向与简介在定位选定后提供建议；仅诊断或用户暂缓时可保留现有呈现。
