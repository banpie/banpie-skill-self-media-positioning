# 信息模板与有限访谈

## 开场与收集原则

先按入口做作者介绍、通俗知识解释和流程说明，不主动讲课程或未解释的比喻。资料统一分三组，标题及含义在无资料、部分资料、资料足够、Skill、Agent 与普通提示词中保持一致：

| 固定分组 | 用日常语言解释 | 包含维度 |
| --- | --- | --- |
| 简历 | 你的基本情况与真实经历 | I01—I06，背景、教育、职业、技能、兴趣等 |
| 个人说明书 | 你的特点、重视的事情与独特资源 | I07—I15，性格、优势不足、故事、使命愿景价值观等 |
| 运营条件 | 这次做账号的目标与可投入条件 | I16—I22，目标、受众想法、时间、边界、业务、账号与平台等 |

这些是信息归类，不是三个必须依次完成的问卷，不要求用户准备三个文件。只有一份简历、一次自由讲述或部分聊天记录，也按同一维度代填。用户不必预先填出定位答案。对来源的维护说明见方法来源文件，不在收集时给用户讲来源历史。

首次说明：“有简历、个人说明书或账号资料可以直接给我，我会代填；没有就照下面写有把握的部分。未知、没有或不愿提供都可以写明。先整理给你核对，你同意后才生成定位；必要时最多再补问一轮、两个问题。不会填可以说‘带我聊’。”

先读取用户本次指定资料，历史资料标注来源及时间，不能视作已核对。只展示一个匹配模板和一个虚构案例。资料已足够时直接代填完整表并等待确认，不再叠加案例。主体不明时用个人模板并注明只是待定映射，不新增分类问卷；明确企业则按同一维度映射。企业、新手、成熟账号都不另造信息模型。

## 统一信息维度

下表是各载体的字段真源。分组帮助理解，不允许把子字段压成“目前情况”等笼统摘要。已知项保留全部与本次账号相关的细节，并标记“本次自述／文件与日期／历史资料待核对”；推断单列。不相关隐私不回显。未知写“未提供”，不适用或不愿提供如实标明。

| 编号 | 分组 | 个人信息维度 | 企业／团队映射 |
| --- | --- | --- | --- |
| I01 | 简历 | 姓名／称呼／花名 | 品牌称呼；操作者与账号代表的主体分开 |
| I02 | 简历 | 性别、年龄、居住地区、语言；婚姻、子女、星座等生活背景（选填） | 品牌号只映射服务地区、工作语言；个人生活背景通常不适用 |
| I03 | 简历 | 学校、学历、专业／教育经历 | 团队专业背景与相关资质；不强求学校学历 |
| I04 | 简历 | 职业、工作／项目经历 | 业务发展、产品服务与交付经历 |
| I05 | 简历 | 技能／特长及实际例子 | 团队交付能力、产品优势与案例 |
| I06 | 简历 | 兴趣、持续多久、愿意投入程度 | 团队愿意持续投入的内容／客户问题，不以老板兴趣代替 |
| I07 | 个人说明书 | 性格／日常表达特点、已有 MBTI 等测评或自述来源 | 品牌性格；出镜者真实表达特点 |
| I08 | 个人说明书 | 优势与不足、已有盖洛普等测评或自述来源 | 组织优势、短板和交付限制 |
| I09 | 个人说明书 | 高光时刻与低谷经历 | 关键成果、失败与复盘；不索取机密 |
| I10 | 个人说明书 | 独特经历、资源与影响力 | 独特资源、案例、渠道与已有信任 |
| I11 | 个人说明书 | 使命 | 企业存在的目的／希望解决的问题 |
| I12 | 个人说明书 | 愿景 | 企业希望长期走向哪里 |
| I13 | 个人说明书 | 价值观及体现它的做法 | 企业价值观、服务原则与真实做法 |
| I14 | 个人说明书 | 已有身份标签／他人评价 | 已有品牌认知、客户评价与团队身份 |
| I15 | 个人说明书 | 想学习或尝试的方向 | 希望探索的内容或能力；区别于已有实力 |
| I16 | 运营条件 | 运营目标及优先级 | 涨粉、引流、变现、品牌传播、招聘等实际目标 |
| I17 | 运营条件 | 目标群体的特征＋核心痛点（如已知） | 观看者、使用者与采购决策者及各自问题 |
| I18 | 运营条件 | 每周可投入时间及其他制作条件 | 团队分工、工时、预算、素材和审核能力 |
| I19 | 运营条件 | 不愿做的事、隐私及表达边界 | 交付、保密、客户素材授权及表达边界 |
| I20 | 运营条件 | 已有产品／服务及变现想法 | 产品、服务范围、真实承接链路；无则注明 |
| I21 | 运营条件 | 账号阶段、内容、受众与结果数据 | 同左；成熟账号补充需保留资产及调整原因 |
| I22 | 运营条件 | 熟悉／考虑的平台、已有资料与其他补充 | 同左；区分已证实的使用习惯和待核验平台建议 |

所有字段保留同一含义及顺序。生活背景和已有测评是可选子项，不是继续分析的条件；已有 MBTI、盖洛普或价值观测评可作为自述材料，没有则用真实经历、自我反思和他人反馈。不要据星座或测评标签断言能力、天赋或赛道。姓名、性别、年龄、教育等可以不提供；技能、兴趣不强求凑够三项。没有资料时展示空模板，已有资料时展示这份模板的代填版，不能改成另一组临时问题或六栏摘要。

## 可复制的填写模板

按当前主体采用上表右侧或左侧含义，下列为个人版。企业用对应映射替换字段说明，不让用户填写不适用的个人属性。不要一次给两份表。

```text
【简历】
姓名／称呼／花名：
性别、年龄、居住地区、语言（可不提供）：
婚姻、子女、星座等生活背景（选填，不影响继续）：
学校、学历、专业／教育经历（可不提供）：
职业、工作／项目经历：
技能／特长及实际例子：
兴趣、持续多久、愿意投入程度：

【个人说明书】
性格／日常表达特点、已有测评或自述来源：
优势与不足、已有测评或自述来源：
高光时刻与低谷经历（可概括或不提供）：
独特经历、资源与影响力：
使命：
愿景：
价值观及体现它的做法：
已有身份标签／他人评价：
想学习或尝试的方向：

【运营条件】
运营目标及优先级：
目标群体的特征＋核心痛点（不知道也可以）：
每周可投入时间及制作条件：
不愿做的事、隐私及表达边界：
已有产品／服务及变现想法：
账号阶段、内容、受众与结果数据：
熟悉／考虑的平台、已有资料与其他补充：
```

这是资料清单，不是二十二道必须答完的问题。自由讲述或发文件都等价，助手负责映射；用户未提供的部分保留未知，不能追缴。

## 虚构填写案例

只展示与本次主体匹配的一列，供用户了解具体程度；例中信息不是本次用户事实。企业案例本身不强制做老板号。

| 编号 | 个人：行政从业者 | 企业：本地厨房设备维护团队 |
| --- | --- | --- |
| I01 | 小禾，公开称呼也用这个 | 小灶维护；运营代填，账号角色未定 |
| I02 | 不提供 | 不适用 |
| I03 | 未提供 | 两位师傅有维修经验，资质未提供 |
| I04 | 五年行政，没做过自媒体 | 六人团队，做本地餐饮设备巡检、维修、保养 |
| I05 | 整理会议记录、表格和报销说明，未统计成效 | 能解释反复故障及维修过程，成效数据未整理 |
| I06 | 办公整理多年；也喜欢周末徒步 | 愿持续讲常见故障与保养，投入程度待验证 |
| I07 | 更习惯写，性格暂未描述 | 希望用朴实易懂的方式解释 |
| I08 | 能把流程写清；不熟悉拍摄 | 师傅经验多；内容整理能力弱 |
| I09 | 写过一页报销说明；低谷不提供 | 未提供，不编造成功案例 |
| I10 | 真实行政实践，可重新编写虚构办公案例；影响力未知 | 可用自己的演示设备；客户现场不能直接公开 |
| I11 | 还没想清楚 | 让本地门店少因设备故障耽误营业 |
| I12 | 希望留下可复用的工作经验 | 愿景未提供 |
| I13 | 不夸大效果，不公开公司内部资料 | 如实解释该修还是该换，不夸张承诺 |
| I14 | 同事常找我整理记录；暂无公开标签 | 已有客户评价未整理 |
| I15 | 想试图文表达 | 想尝试让师傅讲解，但暂无固定出镜人 |
| I16 | 作品积累优先，也想探索职业机会 | 本地有效咨询优先，不追全国粉丝 |
| I17 | 不知道该给谁看 | 门店负责人常问反复故障、该修还是换、保养频次 |
| I18 | 每周三小时；文字为主 | 运营每周半天，两位师傅各半小时 |
| I19 | 不出镜、不公开公司内部资料 | 现场素材须客户同意，不要求老板每天出镜 |
| I20 | 暂不卖课，当前不变现 | 本地维修保养，具体价格未提供 |
| I21 | 无账号，无内容与受众数据 | 发过几条公司介绍，没有整理后台数据 |
| I22 | 平台未定；可提供虚构案例 | 平台未定，暂无数据导出 |

两个案例均足以进入资料核对，不能因为使命、性格、资质等有空白就继续追问。无账号不要求后台数据；有账号优先读已有内容、受众与结果数据，不要求导出全部历史。

## 资料核对与停止位置

用上述 I01—I22 顺序展示三组完整资料表，列为“信息维度／本次已知信息／来源及待核对”。内部编号可不展示。合并来源相同的表格单元也不能省略字段或已知子项。对不相关的敏感维度只写“不用于本次分析”，不曝光具体内容。

不足时先展示已知与缺口、匹配案例，邀请一次自由补充；已有资料足够或已达收集上限时，展示完整表后收尾：

> 以上资料是否对应你这次要做的账号？如果准确，是否现在据此生成定位？可以直接同意开始，也可以修改其中几项。

**在这里结束回复。**不能附个性化赛道、排名、人设、名字或内容支柱。第一条给足资料同样如此，历史记忆不构成确认。仅纠正时更新完整表并等待；纠正同时要求生成时可按修正后信息继续。具体确认语义和有限额度以入口为准。

## 有限补问与短访谈

模板提交后，资料足够就核对生成；不足只补问一轮、最多两个独立问题，澄清与索取资料都计入。只问能改变分析的事实，如运营目标冲突；不追问每个空字段，不让用户先确定黄金三角或目标受众。

用户要求“带我聊”时一次一问，优先问目标、真实经历、投入条件；默认三问后整理完整表，必要时总计最多五问。显示进度，路径切换不重置计数，模板提交后的两问上限同时适用。跳过占用当前问题，连续不知道不换说法重问。

达到上限或用户说“不问了／先给方案”后停止收集，带着未知项进入同一资料核对，取得生成许可后给条件化建议或探索起点；确认不收集新事实，不占额度，也不能借它偷加问题。生成后不重启问卷，额外访谈仅在用户明确要求时约定有限范围。
