# 信息模板与有限访谈

## 首次入门讲解：先解释流程，再进入实践

按入口文件的阶段判断首次开场。已有经验时缩短解释，不自动跳过；用户明确要求跳过或有同一任务的真实续聊进度时才省略。默认用约一百字说明，用户主动要求学习时再展开：

> 定位，就是让一类人在某种情境下，知道为什么要看你的内容。我们会从你做过什么、希望获得什么、能够持续做什么出发，选一个值得尝试的方向，再用反馈修正。先整理资料请你核对，你同意生成后再拿到方向建议和第一步行动，不需要现在就确定一辈子的赛道。

紧接相关填写案例时，用一句话把案例连到定位结果，例如：“下面这位行政从业者，可以先试着帮刚接手行政工作的人处理常见办公难题；这是有经历支撑的候选，还需要反馈验证。”这是一份虚构案例的解释，不是预先替本次用户选方向。企业案例对应“帮本地门店负责人理解厨房设备维护与选择”，按本次场景只选一例。

已懂基础的人用一句说明交代流程，再做任务；不能仅凭履历跳过整个开场。用户只想先学概念时，先回答概念并用例子解释，不强塞个人问卷。辅导中的说明要贴着用户材料，例如解释“选择门店负责人，是因为你的服务范围和客户问题有依据”，不用另讲一大段理论，也不要求回答理解检查题。

## 开场方式

先按入口文件完成首次引导，再看本次可用资料。用户已经主动给出或指定本次业务介绍、经历或账号数据，就代填相关模板并请用户核对与确认生成；不要让其再按模板重写。只有启动语和历史画像时，按模板列出可用的相关信息并标记历史来源；不足进入有限收集，足够也必须先核对与确认生成，不能套用画像抢先定位。老账号及成熟账号优先使用现有材料，参考 [场景适配](scenarios.md)。

没有资料时，选择下方一个相关模板和一个填写案例。账号主体未知时使用兼容模板，沿用个人案例并明确它仅演示填写程度，不代表用户被分类为个人；不要一次展示个人、企业两套长表，不为选模板新增一轮问答。

> 填完有把握的部分，我会按模板整理全部已知信息，请你核对是否对应本次账号；你同意后才生成方向、理由和第一步行动。可以自由讲述、留空或发已有资料。只有影响选择的关键问题，才最多再补问一轮、两个问题。不会填也可以说“带我聊”。

第一次只解释当前入口；用户选短访谈后再说明三问先整理、首次最多五问。不要把可选提示都变成必须回答的子问题，也不把“这题跳过”当成结束整个流程。

### 主体未知时的兼容模板

```text
我／我们的现状（有账号可顺带说明）：
做账号希望获得的主要结果：
做过的事情、能提供的帮助或服务：
愿意持续分享的内容或可用素材：
能投入的条件与不愿做的事情：
已有想法或资料（选填）：
```

## 个人填写模板

每项一两句即可；有把握的先写，没有的留空。受众、变现、平台不需要先想清楚。

```text
目前情况：
做账号希望获得的主要结果：
做过的事情或别人找我帮忙的例子：
喜欢并愿意持续分享的主题：
能投入的时间与不愿做的事情：
已有想法或资料（选填）：
```

按需要解释：目前情况可以是职业、生活阶段或已有账号；具体经历可以是工作、作品、学习和生活实践，不必是巨大成就。兴趣不用列满三项。最后一项可放受众想法、文章、简历、产品或后台数据，但不要求都有。

### 填写案例：普通职场人

以下为虚构示例，只展示具体程度，不是用户事实或理想履历。

```text
目前情况：我做了五年行政，没做过自媒体，平时更习惯写东西。
做账号希望获得的主要结果：把工作经验整理出来，也想看看以后能不能带来职业机会，暂时不准备卖课。
做过的事情或别人找我帮忙的例子：同事常找我整理会议记录和表格。我把公司的报销常见问题整理成过一页说明，具体节省多少时间没统计。
喜欢并愿意持续分享的主题：简单的办公方法、整理和记录，也喜欢周末徒步。还不知道这些能不能放在同一个账号里。
能投入的时间与不愿做的事情：每周三小时；不想出镜，不想把同事和公司的内部资料放到网上。
已有想法或资料：不知道该给谁看。可以提供我自己重新编写的虚构办公案例，目前没有账号数据。
```

这个案例已经足以进入资料核对，用户确认生成后即可提出候选，不应继续索取年龄、学历、性格测评、三项成功经历或完整商业模式。

## 企业填写模板

既可以由老板填写，也可以由运营或团队成员代填。不了解的部分说明未知；不要让操作者代编企业事实。

```text
业务概况：
做账号希望获得的主要结果：
真实客户问题或交付案例：
可持续提供的内容资源：
投入条件与表达边界：
账号现状或已有想法（选填）：
```

业务概况只需产品或服务以及主要服务范围。案例可以是客户反复提的问题，不要求客户名单、合同和交易明细。账号角色未确定时，可以交给后续方案比较。

### 填写案例：小型设备维护公司

以下为虚构示例，数字仅属于案例。

```text
业务概况：我们有六名员工，为本地餐饮门店做厨房设备维护，主要提供巡检、维修和保养。
做账号希望获得的主要结果：让附近有需要的门店找到我们，增加适合服务范围的咨询；不追求全国粉丝。
真实客户问题或交付案例：经常有人问设备为什么反复故障、该修还是该换、保养多久一次。做过不少维修，但案例还没整理，也不能公开客户名称。
可持续提供的内容资源：两位师傅能解释常见故障，可拍自己的演示设备和工具；现场素材需要客户同意后才能使用。
投入条件与表达边界：一名运营每周半天，两位师傅各半小时。不做夸张承诺，也不希望老板每天出镜。
账号现状或已有想法：以前只发过几条公司介绍，没有稳定更新；不确定用公司号还是师傅个人号，没有整理后台数据。
```

这个案例应先按企业模板回显供核对，用户确认生成后围绕本地客户问题、服务范围和团队资源出方向。公司品牌号与师傅专家号是可比较的选择，不能因为老板填写就默认做创始人号。

## 老账号的可选资料

已有账号可提供一个可取得的时间窗口内的内容清单、代表作品、评论问题及目标结果。优先读已有导出，不能要求先导出全部历史。

示例（虚构）：“近两个月发了十条，工具盘点通常三千播放，维修讲解约五百播放，收到四次本地咨询，但没有记录来自哪条。粉丝画像暂时没有。”这能支持粗诊断，不能支持转化归因或行业比较。

## 补问的选择与终点

提问额度以入口文件为准。首次六栏参考模板可留空，不计入短访谈五问；不要把可选栏位变成六个必须答完的问题，也不能追缴所有空栏。模板提交后先按完整模板整理事实，资料足够则核对生成；不足时集中补问一轮、最多两个独立问题；只问会改变选择的内容。例如“你希望主要获得本地维修客户，还是卖给全国同行的培训？”用于澄清目标冲突，不再顺带问价格、平台、团队和预算。

按相关模板全部六栏列出本次全部已知信息，来源及日期就近标明；未知写未提供，推断列为待核对。发现矛盾时，只澄清影响方案的关键冲突；不影响判断的细节保留待确认。预算已用完或用户要求停止时，保留冲突进入资料核对，用户确认生成后再给条件化方案，不继续索取信息，也不自行选一个冲突值作为事实。

用户不知道目标用户、优势、赛道或变现方式时，把对应栏标为未知，不要求用户先完成专业分析；确认生成后再提出假设。连续答“不知道”时不重复追问，停止追问、整理资料并请求生成确认；获准后给低成本探索行动。

## 短访谈兜底

用户要求带着聊时，一次问一个实际问题，优先从以下方向选择尚未知的内容：想得到什么结果；做过的一件具体事情；能持续投入的条件。不是让用户背专业术语。

第三问结束后先展示完整资料表；资料足够就核对生成。剩余问题只解决确实会改变推荐的分歧；总上限五问，分流、澄清、索取资料均计入，跳过也消耗一次。不要机械询问已知信息，不因换成企业、老号、市场研究或用户纠正而重置计数。

若用户连这些也暂时说不清，可以在资料核对并获准生成后交付一周观察练习：记录自己愿意反复做、别人会来请教、能够展示过程的一件事。明确这是寻找依据的起点，尚不足以定出个性化赛道。

## 资料核对示范：资料齐全也先停下

用与用户输入相同的六栏模板完整回显，不省略已知条件。例：

| 个人模板 | 本次已知信息 |
| --- | --- |
| 目前情况 | 五年行政经验；无自媒体账号；习惯写作。本次自述 |
| 做账号希望获得的主要结果 | 整理工作经验、探索职业机会；暂不卖课。本次自述 |
| 做过的事情或别人找我帮忙的例子 | 常整理会议记录、表格，整理过报销说明；成效未统计。本次自述 |
| 喜欢并愿意持续分享的主题 | 办公方法、整理记录；也喜欢徒步。本次自述，徒步素材尚未说明 |
| 能投入的时间与不愿做的事情 | 每周三小时、不出镜、不公开公司内部资料。本次自述 |
| 已有想法或资料（选填） | 受众与平台未确定；愿意提供虚构办公案例；无账号数据。本次自述 |

> 当前资料已足以做初步分析。以上是否对应你这次要做的账号？如果准确，是否现在据此生成定位？你可以直接说“资料正确，开始生成”，也可以修改其中几项。

在这里结束，不能随后附“我已经建议你做行政号”。企业与兼容模板同样逐栏回显，不能只总结优势。
